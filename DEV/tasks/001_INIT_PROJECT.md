## 2. Назначение проекта

Разрабатывается система автоматизации ежемесячного формирования счетов на оплату и УПД в 1С:Бухгалтерия для ООО «ЭЛСИ».

Предполагаемые возможности:

- Формирование ежемесячных счетов.
- Формирование ежемесячных реализаций и УПД.
- Индивидуальные суммы, договоры, объекты и описания услуг.
- Несколько самостоятельных документов для одного контрагента.
- Несколько строк услуг в одном документе.
- Предварительный просмотр и подтверждение документов.
- Защита от повторного создания документов.
- Последующее подключение способов отправки документов.

Точная архитектура и способ интеграции с 1С пока НЕ утверждены.

**В этой задаче запрещено разрабатывать бухгалтерскую функциональность.**

## 4. Проверка безопасности

Репозиторий может быть публичным.

Считай любые данные проекта потенциально конфиденциальными до проверки.

Запрещено публиковать:

- Реальные счета, УПД, договоры и акты.
- Бухгалтерские реестры с реальными данными.

Для разработки используй только вымышленные тестовые данные.

- `*.pdf`
- `*.xlsx`, `*.xls`
- `*.doc`, `*.docx`
- `*.dt`, `*.1CD`
- `*.key`, `*.pfx`, `*.p12`
- `.env`, `.env.*` с исключением `.env.example`
- `/private/`
- `/secrets/`
- `/backups/`
- `/exports/`
- `/data/real/`

Не полагайся только на `.gitignore`.

Перед любым коммитом проверь список добавляемых файлов, staged diff, наличие секретов и реальных бухгалтерских данных.

При сомнениях блокируй публикацию.

Не добавляй в отчёт конфиденциальные сведения, даже если отчёт предназначен только для разработчика.

## 7. Правила заданий и отчётов

Задания хранятся в:

`DEV/tasks/`

Отчёты хранятся в:

`DEV/reports/`

Формат имени:

`NNN_TASK_NAME.md`

Примеры:

`001_INIT_PROJECT.md`

`006_CHANGE_DOCS.md`

Нумерация сквозная, начиная с 001.

Каждому заданию соответствует отчёт с тем же именем.

Задание должно содержать:

- Цель.
- Исходное состояние.
- Разрешённые изменения.
- Запрещённые действия.
- Порядок выполнения.
- Проверки.
- Критерии приёмки.
- Требования к отчёту.

Отчёт должен содержать:

- Статус выполнения.
- Выполненные действия.
- Изменённые файлы.
- Результаты проверок.
- Выявленные проблемы.
- Отклонения от задания.
- Git commit SHA.
- Состояние публикации.
- Нерешённые вопросы.

Допустимые статусы:

`SUCCESS`, `PARTIAL`, `BLOCKED`, `FAILED`.
