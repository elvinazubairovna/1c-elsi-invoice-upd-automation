## Кандидаты для отдельной изолированной среды — без выбора и настройки

Текущий `_APP_SMOKE_016` сообщён как созданный на host. Нельзя считать его изолированным, подключать его к работающей 1С или открывать его там. Сама capability report лишь помогает определить, какие варианты могут быть технически доступны; включённый optional feature или virtualization flag не доказывает защищённую, отключённую от сети среду.

| Кандидат | Что потребуется подтвердить отдельно | Неизвестно сейчас |
|---|---|---|
| Отдельная одноразовая offline VM | Возможность создать гостевую среду, отключить её виртуальную сеть, shared folders/devices/clipboard, подтвердить отсутствие host/production ресурсов; передать в неё отдельный новый disposable clone без live host share и проверить его идентичность внутри guest | Host hypervisor, лицензия/доступность, guest OS и 1С platform/license, способ изолированной передачи и фактическая guest network state |
| Windows Sandbox | Реальная поддержка и разрешённое использование на этой Windows edition, подтверждённое отключение networking и host sharing, установка/лицензирование платформы и отдельная копия данных внутри Sandbox | Edition, feature state, policy/licensing, 1С installer/license и эффективная конфигурация Sandbox |
| Отдельный offline test computer | Физическая/операционная изоляция от сети и production shares, отдельная установка и лицензирование, контролируемая передача distinct clone | Доступность машины, точная сеть, ОС, 1С platform/license и отсутствие общих ресурсов |

Ни один кандидат пока не выбран. Для любого варианта изоляция должна быть доказана на конкретной конфигурации до старта 1С. Может потребоваться отдельная установка 1С и лицензия, которую владелец оформляет самостоятельно. Если позже выбрана VM, задача должна отдельно спроектировать передачу новой distinct disposable copy внутрь гостя с проверкой её идентичности; не подключать каталог host напрямую, не использовать live host share и не передавать production resources. Никаких VM, сети или лицензии в Task 017 не меняли и не проверяли.

Запрещённые shortcuts: отключать все host network adapters; менять host-wide firewall rules, влияющие на production 1С; подключать production data или host production resources ради удобства. Эти способы не создают приемлемого clone-only доказательства и затрагивают задание вне допуска.

Кратчайшая последовательность: дождаться независимого аудита Task 019 и отдельного явного допуска; затем отдельное задание может ограничить владельцу GUI-проверку prerequisites/feature activation и, только если разрешено, проверку пустого Sandbox с disabled network/clipboard. До effective isolation evidence не передавать TEST или установщик и не запускать 1С. Решение и границы подробно описаны в [Windows Sandbox safe setup guide](WINDOWS_SANDBOX_SAFE_SETUP.md); Sandbox, offline VM и offline computer остаются непроверенными кандидатами.

## Цель

После отдельного допуска проверить, что отдельная временная рабочая копия, сделанная из `_RESTORE_CHECK_014`, регистрируется и открывается как отдельная информационная база, и что в ней видна заранее известная владельцу синтетическая тестовая организация. Не просматривать неизвестные записи и не менять данные.

Сравнение файлов и запуск приложения — разные проверки. Файловая parity сверяет структуру, длины и SHA-256 внутри локального drill. Она сама по себе не подтверждает, что база открывается в 1С, что все данные синтетические или что приложение не инициирует фоновые и исходящие действия.

## Обязательные условия до будущего запуска

1. ChatGPT отдельно проверяет этот план и готовит новое задание с точными разрешёнными действиями и границами. До этого никакой запуск не разрешён.
2. Владелец вручную идентифицирует TEST. Task 016 clone tool уже был запущен владельцем после аудита и сообщил о host-side `_APP_SMOKE_016`; этот clone нельзя открывать в 1С, так как его изоляция не подтверждена. Для будущего app test отдельное задание должно предусмотреть distinct disposable clone внутри выбранной изолированной среды; оригиналы `ELSI_TEST`, `_BACKUP_014` и `_RESTORE_CHECK_014` не открывать.
3. Будущее задание должно назвать точные source/destination для клона и подтвердить отсутствие перезаписи. Владелец сверяет точный локальный каталог клона и показывает его в окне регистрации под заметной меткой, например **«ТЕСТ — временная копия для проверки восстановления»**. Не выбирать каталог по истории launcher и не искать production. При сомнении в идентичности — остановиться.
4. Все три исходных объекта — `ELSI_TEST`, `_BACKUP_014` и `_RESTORE_CHECK_014` — сохраняются нетронутыми. Копия для GUI может измениться даже от самого запуска приложения.
5. До запуска должно быть доказано, что гостевой клон не может отправлять данные или обращаться к production. В качестве проверяемого варианта для будущего задания можно рассмотреть отдельную одноразовую виртуальную машину: локально разместить клон внутри неё, отключить все виртуальные сетевые адаптеры, не подключать NAT/bridge/shared network, отключить общие папки, буфер обмена, перетаскивание и диски хоста. Владелец/ответственный специалист должен подтвердить эту изоляцию на конкретной машине и убедиться, что каталог клона не связан с production или общими ресурсами.
6. Доступность такой виртуальной машины и совместимость/лицензирование 1С в отключённой от сети среде не проверены. Не менять сетевые настройки общей рабочей станции, общие службы или настройки production ради этого опыта. Если изоляцию именно для клона нельзя независимо показать и проверить, запуск запрещён.
7. Состояния обменов, ЭДО, почты, API, фоновых заданий, получателей и ранее существовавших записей остаются `UNVERIFIED`. Не считать их выключенными по отсутствию сетевого доступа или успешной файловой копии; сетевую изоляцию нужно проверить отдельно до запуска.

## Критерии и остановка

Успех будущего smoke test можно заявить только при наличии отдельного задания и evidence владельца для каждого пункта:

- `APP_CLONE_BOUNDARY=PASS` — запущен именно отдельный клон.
- `APP_OUTBOUND_ISOLATION=PASS` — изоляция клона проверена до запуска.
- `APP_OPEN=PASS` — приложение открыло базу без непредвиденной сетевой активности.
- `SYNTHETIC_ORGANIZATION_VISIBLE=PASS` — видна только заранее известная синтетическая организация.
- `NO_SEND=PASS` — ничего не отправлялось и не запускались обмены.
- `NO_PRODUCTION_ACCESS=PASS` — владелец подтверждает, что production не выбиралась и не затрагивалась.

Если идентичность базы, изоляция, видимые данные или поведение приложения неожиданны: не продолжать, не передавать скриншоты/данные, штатно закрыть приложение, оставить все оригиналы и клон нетронутыми до отдельного решения. Не использовать production как fallback. Не сообщать пароли или лицензии.

## Сохранность и ограничения

`ELSI_TEST`, `_BACKUP_014` и `_RESTORE_CHECK_014` сохраняются и не используются как рабочие базы. На момент Task 016 инструмент не запускался; позднее владелец сообщил об одном успешном создании `_APP_SMOKE_016`. Этот каталог — owner-reported host-side clone, Codex его не осматривал, и он не считается изолированным. Capability script Task 017 не запускался на host. Будущий distinct disposable clone может быть изменён приложением; создание/передача/проверка и любое удаление/замена требуют отдельного задания. В Task 017 реальные файлы не копировали, не открывали и не меняли.

Даже успешное открытие проверяет только базовую file-level/application-level пригодность указанной копии. Оно не подтверждает полноту или синтетичность всех записей, целостность каждого процесса 1С, безопасность интеграций за пределами изоляции, права пользователей, совместимость `.epf`/`.cfe`, генерацию счетов/УПД или production readiness. Архитектура остаётся `NOT_APPROVED`; генератор счетов/УПД не реализован.
