# Порядок разработки и аудита

1. Владелец получает от ChatGPT готовый файл задания `NNN_TASK_NAME.md` и помещает его в `DEV/tasks/`.
2. Codex читает `AGENTS.md` и соответствующее задание, выполняет только перечисленную область. Если нужное техническое решение не дано, работу следует остановить и передать вопрос владельцу для согласования с ChatGPT.
3. До изменений Codex проверяет Git state, ветку, базовый SHA и разрешённые пути. Посторонние пользовательские файлы и изменения сохраняются и не включаются в коммит.
4. Codex реализует только разрешённые изменения, запускает предусмотренные проверки и записывает факты в `DEV/reports/NNN_TASK_NAME.md`. Статус указывается честно: `SUCCESS`, `PARTIAL`, `BLOCKED` или `FAILED`.
5. Перед коммитом нужно просмотреть список файлов, staged diff и результат `pwsh -NoProfile -File DEV/tools/Test-Publication.ps1 -Mode Index`. Перед push нужно проверить все отправляемые версии файлов через `-Mode Outgoing`. Локальные hooks помогают, но могут быть отключены или обойдены; ручные запуски обязательны.
6. Отчёт содержит перечень изменённых файлов, точные команды и результаты проверок, ограничения и отклонения, Git status, статус публикации, ссылку на опубликованный отчёт и SHA, известные на момент подготовки отчёта. Удалите из отчёта персональные данные, секреты и подробные значения срабатываний. Не указывайте SHA коммита, содержащего этот же отчёт, как известный заранее.
7. После успешного коммита и push Codex сообщает владельцу итоговый удалённый HEAD SHA и ссылку на отчёт. Если отчёт входит в этот коммит, не создавайте дополнительный коммит только ради вписывания его SHA в сам отчёт.
8. Только ChatGPT проводит аудит результата и устанавливает `ACCEPTED`, `REWORK_REQUIRED` или `BLOCKED`. Codex не объявляет аудит завершённым и не начинает следующую задачу самостоятельно.

## Локальные проверки

- До коммита: `pwsh -NoProfile -File DEV/tools/Test-Publication.ps1 -Mode Index`.
- До push: `pwsh -NoProfile -File DEV/tools/Test-Publication.ps1 -Mode Outgoing` с теми же ref updates, которые будут отправлены.
- Проверки безопасности: `pwsh -NoProfile -File tests/security/Invoke-SecurityTests.ps1`.

Проверки анализируют известные опасные файлы и шаблоны, но не гарантируют отсутствие всех конфиденциальных данных. Ручной аудит содержимого обязателен. GitHub Actions проверяет опубликованное состояние и не предотвращает первое раскрытие в публичном репозитории.
