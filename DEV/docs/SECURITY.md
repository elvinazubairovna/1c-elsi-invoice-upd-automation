# Безопасность

Код и вымышленные тестовые данные должны храниться отдельно от реальных бухгалтерских данных. Не помещайте реальные документы, реестры, ИНН/КПП, банковские реквизиты, персональные данные, адреса объектов, суммы договоров, сведения контрагентов, выгрузки/резервные копии 1С, пароли, API-ключи, токены, сертификаты, закрытые ключи ЭЦП или локальные конфигурации с чувствительной информацией в репозиторий.

Для разработки применяйте только вымышленные тестовые данные. `.gitignore` помогает исключать типовые файлы, но не заменяет проверку содержимого.

Перед каждым коммитом проверьте список файлов, staged diff, наличие секретов и реальных бухгалтерских данных, а также отсутствие случайно добавленных документов. При сомнениях не публикуйте изменения. Не используйте `git push --force`.

## Автоматические проверки и их ограничения

`DEV/tools/Test-Publication.ps1` проверяет содержимое Git index перед коммитом, отслеживаемое дерево для CI и все версии файлов во всех outgoing-коммитах перед push. Проверяются опасные расширения и каталоги, некоторые известные шаблоны секретов, контрольные цифры российских ИНН и дополнительные признаки реальных бухгалтерских документов. Локальные hooks запускают те же режимы, а workflow повторяет проверки после публикации.

Эти проверки не гарантируют обнаружение всех персональных данных, секретов, обфусцированных или новых форматов. Неизвестные бинарные файлы и неподдерживаемые кодировки блокируются. Не обходите результат проверки: вручную просматривайте содержимое файлов, staged diff и каждый outgoing-коммит. GitHub Actions запускается после публикации и не может предотвратить первоначальное раскрытие в публичном репозитории. Не помещайте в тесты реальные сведения; используйте только синтетические примеры.
