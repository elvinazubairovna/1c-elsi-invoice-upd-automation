# 1c-elsi-invoice-upd-automation

Проект предназначен для автоматизации ежемесячного формирования счетов на оплату и УПД в 1С:Бухгалтерия для ООО «ЭЛСИ». Точная архитектура и способ интеграции с 1С пока не утверждены.

## Структура

- `src/` — исходный код.
- `tests/` — тесты на вымышленных данных.
- `DEV/tasks/` — утверждённые задания.
- `DEV/reports/` — отчёты о выполнении.
- `DEV/docs/` — требования, архитектура и безопасность.

## Каноническая документация

- [Подтверждённые требования](DEV/docs/REQUIREMENTS.md) и [статус реализации](DEV/docs/IMPLEMENTATION_STATUS.md).
- [Архитектура](DEV/docs/ARCHITECTURE.md) и [безопасность](DEV/docs/SECURITY.md).
- [Порядок разработки и аудита](DEV/docs/DEVELOPMENT_WORKFLOW.md), [история изменений по задачам](DEV/docs/CHANGELOG.md) и [шаблон задания](DEV/docs/TASK_TEMPLATE.md).

После каждой задачи сверяйте документы с фактическими изменениями, тестами, конфигурацией и ограничениями. Обновляйте все затронутые канонические документы и `IMPLEMENTATION_STATUS.md` вместе с задачей; перед публикацией включайте в отчёт таблицу `Documentation reconciliation`. Заявления без проверяемых доказательств помечайте `UNVERIFIED` или `NOT_IMPLEMENTED`. Автоматические проверки и hooks не заменяют ручной аудит.

Перед работой прочитайте `AGENTS.md` и соответствующее задание в `DEV/tasks/`. Выполняйте только его область изменений и документируйте результат в `DEV/reports/`.

Порядок локальных проверок, коммитов, публикации и аудита описан в [`DEV/docs/DEVELOPMENT_WORKFLOW.md`](DEV/docs/DEVELOPMENT_WORKFLOW.md). Автоматические проверки помогают обнаружить известные опасные файлы и шаблоны, но не гарантируют отсутствия всех конфиденциальных данных: ручной просмотр содержимого коммита и outgoing-коммитов обязателен. GitHub Actions запускается после публикации и не предотвращает раскрытие при первом push.

**Конфиденциальность:** не добавляйте реальные бухгалтерские документы, данные контрагентов и сотрудников, реквизиты, выгрузки 1С, секреты или локальные конфигурации. Для разработки используйте только вымышленные данные. Перед каждым коммитом отдельно проверяйте содержимое файлов; `.gitignore` сам по себе не является защитой.
